# Browser Agent

Автономный AI-агент, который управляет настоящим браузером (Playwright +
Chromium) и решает многошаговые задачи на произвольных сайтах: ищет
информацию, заполняет формы, кликает по элементам, читает контент страниц и
принимает решения о следующем шаге - так же, как это делал бы человек.

Агент работает с любым LLM-провайдером, совместимым с Anthropic Messages
API (Claude, OpenRouter, z.ai GLM и т.д.) - смена провайдера сводится к
правке `.env`, без изменений кода.

## Возможности

- **Восприятие страницы без хардкода селекторов.** На каждом шаге в страницу
  инжектируется JS, который сканирует живой DOM, находит интерактивные
  элементы (ссылки, кнопки, поля ввода, select, contenteditable и т.д.) и
  присваивает им числовые ID. Агент ссылается на элементы только по этим ID.
- **Vision и text-only режимы.** В vision-режиме агент дополнительно получает
  скриншот с подписанными ID элементов. В text-only режиме (по умолчанию)
  решения принимаются только по текстовому списку элементов - это быстрее и
  дешевле, и хорошо работает с моделями без поддержки изображений.
- **Чтение текста страницы.** Отдельный инструмент `read_page_text` достаёт
  видимый текст страницы (или конкретного элемента) - для чтения описаний
  вакансий, статей, резюме и т.п., которые не входят в список интерактивных
  элементов.
- **Поддержка нескольких вкладок.** Если клик открывает новую вкладку, агент
  автоматически переключается на неё и может вернуться обратно через
  `close_tab`.
- **Цикл "восприятие -> решение -> действие".** На каждом шаге агент видит
  актуальное состояние страницы, выбирает один инструмент и действие,
  выполняет его и снова оценивает результат - без жёсткого плана,
  составленного заранее.
- **Рабочие заметки (scratchpad).** Инструмент `update_notes` позволяет
  агенту вести короткую "память" (план, прогресс, найденные факты), которая
  не вырезается при сжатии контекста на длинных задачах.
- **Управление контекстом.** Старые наблюдения (описание страницы +
  скриншот) автоматически сворачиваются, оставляя только последние N -
  рассуждения и действия агента при этом сохраняются полностью.
- **Устойчивость к зависаниям LLM.** Вызовы провайдера ограничены таймаутом
  с автоматическими повторами.
- **`ask_user` / `finish_task`.** Агент может приостановиться и задать вопрос
  пользователю (например, при реальной стене логина или необходимости
  принять решение, которое явно оставлено пользователю) или завершить задачу
  с итоговым summary.

## Архитектура

```
                      ┌─────────────────────────┐
                      │        AgentLoop         │
                      │   (perceive→decide→act)  │
                      └────────────┬─────────────┘
                                    │
        ┌───────────────┬──────────┼───────────────┬────────────────┐
        ▼                ▼          ▼               ▼                ▼
 BrowserController  perception.py  LLMClient   tools/dispatcher  tools/schema
 (Playwright,       (set-of-marks   (Anthropic   (execute_tool ->  (TOOLS:
  context manager)   DOM scan +     Messages API  click/type_text/  navigate,
                      screenshot)    + timeout/    scroll/...)       click,
                                     retry)                          type_text,
                                                                      scroll,
                                                                      press_key,
                                                                      go_back,
                                                                      read_page_text,
                                                                      close_tab,
                                                                      update_notes,
                                                                      ask_user,
                                                                      finish_task)
```

### Перечень компонентов

- **`agent/browser/controller.py`** - `BrowserController` владеет жизненным
  циклом Playwright (браузер/контекст/страница), используется как async
  context manager. Поддерживает обычный запуск и постоянный профиль
  (`user_data_dir`) для сохранения сессий между запусками.
- **`agent/browser/perception.py` + `perception.js`** - "set-of-marks"
  восприятие: инжектирует JS, сканирует живой DOM, находит интерактивные
  элементы, присваивает им числовые ID, рисует на скриншоте красные рамки с
  номерами и возвращает `PageState` (url, title, список `ElementInfo`,
  скриншот). ID элементов валидны только до следующего изменения страницы -
  пересканирование происходит после каждого действия.
- **`agent/browser/actions.py`** - выполняет действия (click, type_text,
  scroll, press_key) над элементами по числовому ID через
  `window.__agentElements`. Использует настоящие события мыши/клавиатуры (а
  не `element.click()`/`.value =`), чтобы JS-обработчики страницы срабатывали
  как обычно.
- **`agent/core/observation.py`** - превращает `PageState` в content blocks
  для LLM: текстовое описание видимых элементов и, опционально, скриншот.
- **`agent/core/prompts.py`** - `build_system_prompt(vision)` собирает
  системный промпт: одно действие за ход, без жёсткого плана наперёд,
  переоценка состояния после каждого шага, правила автономности (не
  спрашивать пользователя то, что можно прочитать на странице самому,
  расширять слишком узкие фильтры локации, проверять результат деструктивных
  действий и т.д.).
- **`agent/core/llm_client.py`** - тонкая async-обёртка над
  `anthropic.Anthropic().messages.create` с таймаутом и повторами при
  зависании провайдера. Работает с любым Anthropic-Messages-API-совместимым
  провайдером через `base_url`.
- **`agent/core/context.py`** - `trim_history()`: управление контекстом.
  Оставляет в полном виде только последние `CONTEXT_KEEP_LAST` наблюдений
  (описание страницы + скриншот); более старые заменяются короткой
  заглушкой. Сообщения агента (рассуждения и действия) не обрезаются никогда.
- **`agent/core/loop.py`** - `AgentLoop.run(task, on_step=...)`: основной
  цикл. Обрабатывает вызовы инструментов, `ask_user` (приостановка до ответа
  через injectable async callback), `finish_task` (возвращает
  `AgentResult`), `update_notes` и `MAX_STEPS`. `on_step(StepEvent)`
  вызывается после каждого шага для UI/логирования.
- **`agent/tools/schema.py`** - `TOOLS`: фиксированный, независимый от
  задачи набор инструментов, доступных LLM (navigate, click, type_text,
  scroll, press_key, go_back, read_page_text, close_tab, update_notes,
  ask_user, finish_task).
- **`agent/tools/dispatcher.py`** - `execute_tool()` сопоставляет вызов
  инструмента с реализацией в `agent/browser/actions.py` и возвращает
  `ToolResult` (текст результата + флаги `finished`/`success`/
  `ask_user_question`/`new_page`). Перехватывает `ElementNotFoundError` и
  ошибки Playwright, чтобы одно неудачное действие не приводило к падению
  всего цикла.
- **`agent/config.py`** - загружает `.env` и определяет провайдера LLM,
  `VISION_ENABLED`, `MAX_STEPS`, `CONTEXT_KEEP_LAST`, `LLM_TIMEOUT`.

### Цикл работы агента

1. `BrowserController` открывает/обновляет страницу.
2. `perception.capture_state` сканирует DOM и (опционально) делает скриншот
   с подписанными элементами.
3. `observation.build_observation` превращает это в content blocks для LLM.
4. `LLMClient.step` отправляет системный промпт + историю + наблюдение и
   получает один вызов инструмента.
5. `tools/dispatcher.execute_tool` выполняет действие в браузере.
6. Результат добавляется в историю, `context.trim_history` подрезает старые
   наблюдения, и цикл повторяется - пока агент не вызовет `finish_task`,
   `ask_user`, либо не будет достигнут `MAX_STEPS`.

## Установка (Windows, PowerShell)

Требуется **Python 3.13** (Python 3.14 пока несовместим с зависимостью
Playwright `greenlet`).

```powershell
py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
playwright install chromium
```

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните ключи:

```powershell
Copy-Item .env.example .env
```

Провайдер LLM выбирается автоматически по тому, какой ключ задан (приоритет
сверху вниз):

| Переменные | Провайдер |
| --- | --- |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Прямой доступ к Anthropic API |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | OpenRouter (любая модель через Anthropic-совместимый эндпоинт) |
| `ZAI_API_KEY`, `ZAI_BASE_URL`, `ZAI_MODEL` | z.ai (бесплатные модели GLM) |

Дополнительные переменные:

- `AGENT_VISION=true` - включить отправку скриншотов модели (для
  vision-моделей, например Claude).
- `AGENT_MAX_STEPS` - лимит шагов на задачу (по умолчанию 50).
- `AGENT_CONTEXT_KEEP_LAST` - сколько последних наблюдений хранить в полном
  виде (по умолчанию 3).
- `AGENT_LLM_TIMEOUT` - таймаут одного вызова LLM в секундах (по умолчанию
  60).

**`.env` не коммитится** (см. `.gitignore`) - храните в нём только свои
реальные ключи, а в `.env.example` оставляйте плейсхолдеры/комментарии.

## Запуск

### Интерактивный агент

```powershell
python scripts/run_agent.py
```

Откроется видимое окно Chromium с постоянным профилем `.agent_profile/`
(сессии/логины сохраняются между запусками) и приглашение `Task>` в
терминале - вводите задачи на естественном языке.

### Stage 0: проверка окружения

```powershell
python scripts/healthcheck.py
```

Должно открыться видимое окно Chromium с example.com, и в
`runs/healthcheck.png` появится скриншот.

### Демонстрация восприятия страницы

```powershell
python scripts/demo_perception.py
```

## Тесты

```powershell
pytest
```

Запустить один файл/тест:

```powershell
pytest tests/integration/test_perception.py
pytest tests/integration/test_llm_step.py::test_agent_picks_search_input_for_search_task
```

Тесты, обращающиеся к LLM API, автоматически пропускаются, если не настроен
ключ (`requires_api_key` в `tests/integration/test_llm_step.py`, проверяет
`config.LLM_API_KEY`). `pytest.ini` устанавливает `asyncio_mode = auto`,
поэтому асинхронные тесты не требуют `@pytest.mark.asyncio`.

## Безопасность и автономность

Системный промпт (`agent/core/prompts.py`) явно разрешает агенту выполнять
действия, описанные в задаче (отклики на вакансии, оформление заказов,
удаление писем), не переспрашивая на каждом шаге. `ask_user` вызывается
только при реальной нехватке информации, стене логина/капче или на шаге,
который пользователь явно попросил остановить (например, перед оплатой).

Учитывайте это при формулировке задач: если какой-то шаг должен требовать
подтверждения (например, финальное подтверждение оплаты), укажите это явно
в тексте задачи.
